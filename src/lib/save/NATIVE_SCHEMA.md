# Android-native save schema → upstream `player`

The Android app's **Export to mobile** (`AntimatterDimensionsAndroidSaveFormat` + `AAA`, gzip,
`EndOfSavefile`) carries an Android-native player object. **Export to web/steam** carries the
upstream schema (`src/core/player.js` at the pinned SHA, `version: 25`). This table maps the
native keys onto upstream keys for `normalize.ts`.

## Evidence

- `fixtures/saves/android-3.18.0-native-eternity-paired.txt` and
  `android-3.18.0-web-export-eternity-paired.txt` hold one game state exported both ways, native
  first and web ~80 s later. Counters that grow while the game runs (antimatter, IP, EP,
  infinities, play time) differ slightly. Everything else must be equal.
- The other native fixtures (3.17.0 pre-break, 3.18.0 pre-eternity and early-eternity) have the
  same 63 top-level keys. They help where the paired values are all zero.
- Native Decimals are `{ "mantissa": m, "exponent": e }` objects. Upstream Decimals are strings
  like `"1.0e+491"`. `parseBigNum` reads both.

## Status legend

| Status       | Meaning                                                                                                         |
| ------------ | --------------------------------------------------------------------------------------------------------------- |
| **verified** | Same value in the paired fixtures, under the same key or a renamed key.                                         |
| **inferred** | The name and shape match, but the fixtures can't confirm the encoding (for example, every value is 0 or empty). |
| **differs**  | Same key name with a different encoding, or values that disagree. Not read.                                     |
| **unmapped** | No upstream counterpart, or the meaning is unknown. Not read.                                                   |
| **ignored**  | Same key in both schemas, but not needed for `NormalizedSave` (options, cosmetics, and similar).                |

`NormalizedSave` reads only verified and inferred keys. Reading an inferred key is noted under "Used by".

## `NormalizedSave` fields that are undefined for native saves

- `version.save`: the native schema has no player-data version.

Every other `NormalizedSave` field comes from a verified or inferred mapping above. The inferred
fields (`bankedInfinities`, `eternityChallenges`, `realityUpgrades`, `perks`, `imaginaryUpgrades`,
`imaginaryRebuyableLevels`) are 0 or empty in every native fixture. Check them again once a
native export from an EC, Reality, Perk or Imaginary Machine stage is captured.
